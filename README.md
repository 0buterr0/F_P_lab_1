# Лабораторна робота №1 — «Інформаційні ресурси кафедри»

Консольна інформаційна система на Haskell з базою даних MySQL.
Можна вводити, коригувати й видаляти дані в усіх 8 таблицях, шукати ресурси за різними
критеріями й будувати звіти зі статистики використання.

## Структура проєкту

```
dept-resources/
├── dept-resources.cabal     опис проєкту для cabal
├── docker-compose.yml       MySQL 8.0 у Docker (найпростіший спосіб)
├── app/Main.hs              точка входу, підключення до БД
├── src/
│   ├── Db/Value.hs          класи FromValue, ToValue, FromRow + екземпляри
│   ├── Db.hs                підключення, виконання запитів
│   ├── Entity.hs            клас Entity з CRUD-методами за замовчуванням
│   ├── Display.hs           клас Display, друк таблиць
│   ├── Input.hs             класи Field, Editable; введення з перевіркою
│   ├── Model.hs             8 типів даних і їхні екземпляри класів
│   ├── Search.hs            пошук (JOIN-запити) і звіти
│   └── Menu.hs              меню (одна поліморфна функція для всіх таблиць)
└── sql/
    ├── schema.sql           створення БД, 8 таблиць, тестові дані
    └── create_user.sql      користувач lab/lab (для ручного встановлення MySQL)
```

## База даних (8 таблиць)

| Таблиця            | Що зберігає (з вимог завдання)                                                    |
|--------------------|-----------------------------------------------------------------------------------|
| `resources`        | назва ресурсу, текст анотації, дата відкриття, термін використання, умови використання |
| `resource_types`   | вид ресурсу (довідник)                                                            |
| `purposes`         | призначення (довідник)                                                            |
| `authors`          | автори: ПІБ, посада, ступінь, e-mail                                              |
| `resource_authors` | зв'язок «ресурс – автор» (багато-до-багатьох) з роллю автора                      |
| `resource_urls`    | адреси ресурсу в мережі (у ресурсу їх може бути кілька)                           |
| `users`            | інформація про користувачів                                                       |
| `usage_stats`      | статистика використання: хто, коли, який ресурс, дія, тривалість                  |

Цілісність даних забезпечують зовнішні ключі (CASCADE / RESTRICT), обмеження UNIQUE і CHECK.

## Класи типів і екземпляри

| Клас        | Призначення                                      | Екземпляри                                           |
|-------------|--------------------------------------------------|------------------------------------------------------|
| `FromValue` | значення MySQL → тип Haskell                     | `Int`, `Text`, `Day`, `LocalTime`, `Maybe a`         |
| `ToValue`   | тип Haskell → параметр SQL                       | `Int`, `Text`, `Day`, `LocalTime`, `Maybe a`         |
| `FromRow`   | рядок результату → запис                         | усі 8 сутностей + `ResourceView` (результат JOIN)    |
| `Entity`    | таблиця БД; `findAll`, `findById`, `insert`, `update`, `delete` — методи за замовчуванням | усі 8 сутностей |
| `Display`   | короткий і повний текстовий вигляд               | усі 8 сутностей + `ResourceView`                     |
| `Field`     | розбір і показ значення поля під час введення    | `Int`, `Text`, `Day`, `LocalTime`, `Maybe a`         |
| `Editable`  | введення нового запису та коригування наявного   | усі 8 сутностей                                      |

`Entity` має суперклас `FromRow`. Екземпляру достатньо вказати назву таблиці, колонки, `toRow`
і `getKey`, а SQL для CRUD генерується в методах за замовчуванням. Функція `entityMenu` у
`Menu.hs` одна на всі таблиці: вона працює з будь-яким типом `a`, для якого є
`(Entity a, Display a, Editable a)`.

## Запуск

### Крок 1. Встановити й запустити MySQL

Підійде будь-який із трьох варіантів.

**Варіант А — Docker (рекомендовано).** Потрібен [Docker Desktop](https://www.docker.com/products/docker-desktop/).
У папці проєкту виконай:

```powershell
docker compose up -d
```

Під час першого запуску буде створено базу `dept_resources`, користувача `lab` / `lab`,
виконається `sql/schema.sql` з тестовими даними. Переконатися, що все працює:

```powershell
docker exec -it dept-resources-mysql mysql -ulab -plab dept_resources -e "SELECT id, title FROM resources;"
```

Скинути базу до початкового стану: `docker compose down -v`, потім `docker compose up -d`.

**Варіант Б — XAMPP (MariaDB, сумісна з MySQL).** Встанови XAMPP, у XAMPP Control Panel
натисни *Start* навпроти *MySQL*. Потім у PowerShell:

```powershell
cd C:\xampp\mysql\bin
.\mysql.exe -u root -e "source C:/шлях/до/dept-resources/sql/schema.sql"
.\mysql.exe -u root -e "source C:/шлях/до/dept-resources/sql/create_user.sql"
```

**Варіант В — MySQL Community Server** (інсталятор з dev.mysql.com). Після встановлення:

```powershell
mysql -u root -p -e "source C:/шлях/до/dept-resources/sql/schema.sql"
mysql -u root -p -e "source C:/шлях/до/dept-resources/sql/create_user.sql"
```

### Крок 2. Зібрати й запустити програму

```powershell
cabal update
cabal run
```

Перша збірка триває кілька хвилин, бо завантажується драйвер `mysql-haskell` і його залежності.
Цей драйвер написано на чистому Haskell, тож бібліотеки MySQL на C встановлювати не потрібно.

### Кирилиця в консолі Windows

Запускай програму у **Windows Terminal** (у Windows 11 він стоїть за замовчуванням), перед цим виконавши:

```powershell
chcp 65001
```

Якщо після цього українські літери у введенні все одно не розпізнаються, запусти так:
`cabal run dept-resources -- +RTS --io-manager=native -RTS`.

### Інші параметри підключення

За замовчуванням програма підключається до `127.0.0.1:3306`, база `dept_resources`, користувач `lab` / `lab`.
Змінити це можна змінними середовища:

```powershell
$env:MYSQL_HOST="127.0.0.1"; $env:MYSQL_PORT="3307"
$env:MYSQL_USER="root"; $env:MYSQL_PASSWORD="secret"; $env:MYSQL_DATABASE="dept_resources"
cabal run
```

## Можливості програми

**Головне меню:** пункти 1–8 — таблиці, 9 — пошук, 10 — звіти.

**Робота з кожною таблицею:** перегляд усіх записів, перегляд за id, додавання, редагування,
видалення з підтвердженням.
- Під час редагування Enter залишає поточне значення поля, а `-` очищає необов'язкове поле (NULL).
- Для зовнішніх ключів (вид, призначення, ресурс, автор, користувач) програма показує список
  наявних записів і перевіряє, що введений id існує.
- Помилки БД показуються зрозумілим повідомленням, програма при цьому не завершується.
  Наприклад, видалити вид ресурсу, до якого прив'язані ресурси, не вийде.

**Пошук ресурсів:**
- за ключовим словом у назві чи анотації;
- за автором;
- за видом;
- за призначенням;
- за періодом дати відкриття;
- ресурси, доступні на вказану дату (з урахуванням терміну використання);
- за фрагментом URL;
- комбінований пошук (кілька критеріїв одночасно);
- повна картка ресурсу з авторами, адресами та статистикою.

**Звіти:**
- популярність ресурсів;
- активність користувачів;
- використання за видами ресурсів;
- використання за місяцями;
- звернення за період;
- стан терміну використання (діє / завершився / безстроково);
- загальні показники системи.

## Типові проблеми

| Симптом | Що зробити |
|---|---|
| `Connection refused` | MySQL не запущено, або він працює на іншому порту (див. `MYSQL_PORT`) |
| `Access denied for user 'lab'` | не виконано `create_user.sql` (варіанти Б/В) |
| Помилка `auth plugin` / `caching_sha2_password` | `cabal update` (потрібен `mysql-haskell` ≥ 1.2) або виконати в MySQL: `ALTER USER 'lab'@'%' IDENTIFIED WITH mysql_native_password BY 'lab';` |
| `Unknown database` | не виконано `schema.sql` |
| Порт 3306 зайнятий (у Docker) | у `docker-compose.yml` змінити `"3306:3306"` на `"3307:3306"` і задати `MYSQL_PORT=3307` |
